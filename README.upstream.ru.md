# Ethernet First — приоритет проводного интернета в Windows

[![Windows tests](https://github.com/w1zardz/windows-ethernet-first/actions/workflows/test.yml/badge.svg)](https://github.com/w1zardz/windows-ethernet-first/actions/workflows/test.yml)

[English documentation](README.en.md) · [MIT License](LICENSE)

**Windows использует интернет iPhone по USB вместо Ethernet?** Ethernet First
проверяет соединения, отдаёт приоритет работающему проводному интернету и
уведомляет о переходе на USB-модем или Wi-Fi. Открытый PowerShell-скрипт для
Windows 10/11, без установки Python и сторонних библиотек.

## Что происходит при подключении iPhone к компьютеру

USB-модем iPhone отображается как **Apple Mobile Device Ethernet**. Windows
может выбрать его вместо домашнего интернета: автоматическая метрика учитывает
скорость сетевого интерфейса, а не реальную скорость мобильного оператора.
Обычный USB → Ethernet адаптер при этом остаётся проводным подключением.

## Установка

1. [Скачайте ZIP](https://github.com/w1zardz/windows-ethernet-first/archive/refs/heads/main.zip) и распакуйте архив.
2. Запустите **install.bat** и подтвердите системный запрос администратора.
3. Значок Ethernet First появится в области уведомлений. Проверка запускается
   каждые 15 секунд и автоматически при входе в Windows.

Установка предназначена для текущего пользователя с правами администратора.
Рабочие файлы находятся в `C:\Program Files\EthernetFirst`, состояние и резервные
метрики — в `C:\ProgramData\EthernetFirst`. Это локальная задача планировщика
Windows, а не служба: она работает, пока этот пользователь вошёл в систему.

## Логика выбора сети

- Приоритет: **исправный Ethernet → Wi-Fi → USB-модем / распознанный hotspot**.
- Интернет проверяется TCP-подключениями к нескольким независимым адресам на порту
  443, с привязкой к исходному адресу **и** конкретному интерфейсу.
- Два успешных цикла подтверждают доступность; три неудачных — потерю доступа.
  Неисправный Ethernet получает более низкий приоритет только при наличии
  проверенного работающего запасного подключения.
- IPv4 и IPv6 проверяются независимо. Скорость линка «1 Гбит/с» не считается
  доказательством доступа в интернет. Тестов пропускной способности нет.
- Телефон и Wi-Fi остаются включёнными для резервного доступа.
- Сохраняются первоначальные метрики по GUID адаптера: изменение номера
  интерфейса после переподключения не ломает восстановление.

## Уведомления и VPN

Уведомление появляется при изменении состояния; частота ограничена, чтобы не
засыпать экран сообщениями. Windows Focus Assist / «Не беспокоить» может
скрывать уведомления. Подробности всегда доступны в `status.json` и `events.log`.

Скрипт изменяет только метрики физических интерфейсов. Настройки VPN и таблица
отдельных маршрутов не редактируются. Метрики сохраняют более высокий приоритет
существующих виртуальных default-маршрутов. Это **не обещание переключить каждый
пакет**: более специфичные маршруты, существующие соединения, VPN endpoint и
приложения с привязкой к интерфейсу могут продолжить использовать другую сеть.
При трафике на распознанном мобильном адаптере скрипт отдельно предупреждает
об этом — даже если проводной маршрут уже предпочтителен. Учитываются байты
адаптера, включая локальный трафик: это сигнал для проверки, не счётчик тарифа.
Также предупреждает о трафике Wi-Fi при работающем Ethernet, поскольку hotspot
телефона может называться произвольно. Уведомления поддерживают русский и
английский языки; язык выбирается по Windows, либо параметром `-Language ru`.

Скрипт не чинит скорость VPN, MTU, DPI, перегрузку сервера или ограничения тарифа.
Например, 90 Мбит/с напрямую и 0,1 Мбит/с отдачи через VPN требуют отдельной
диагностики туннеля. Сравнивайте один и тот же тестовый сервер.

## Как распознаётся режим модема по Wi-Fi

По имени адаптера невозможно надёжно определить, подключён ли Wi-Fi к телефону
или роутеру. Названия профилей с `iPhone`, `iPad`, `Personal Hotspot` распознаются
эвристически. Любой другой Wi-Fi всё равно уступает работающему Ethernet.
Для своего hotspot задайте тип по GUID адаптера в установленном `config.json`:

```powershell
Get-NetAdapter | Select-Object Name, InterfaceDescription, InterfaceGuid
```

```json
{
  "adapterOverrides": {
    "{GUID-ВАШЕГО-АДАПТЕРА}": "Mobile"
  }
}
```

Допустимые типы: `Wired`, `WiFi`, `Mobile`, `Virtual`, `Other`. Настройка относится
ко всему адаптеру, включая другие Wi-Fi-сети. После изменения перезапустите
задачу EthernetFirst. Не обозначайте VPN как физический интерфейс.

## Проверить без изменения настроек

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\EthernetFirst.ps1 -Once
```

Непрерывное наблюдение без изменения метрик:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\EthernetFirst.ps1
```

Без установки состояние сохраняется в `%LOCALAPPDATA%\EthernetFirst`.
Для изменения метрик вручную запустите от администратора с параметром `-Apply`.

## Удаление и откат

Запустите **uninstall.bat**: задача остановится, исходные метрики восстановятся,
автозапуск будет удалён. Файлы и резервная копия сохраняются. Если адаптер
физически отсутствует и восстановить его нельзя, подключите его и повторите
удаление: незавершённая запись останется в резервной копии.

Если раньше запускали `-Apply` вручную, остановите этот процесс и выполните
`EthernetFirst.ps1 -Restore` от администратора с тем же `-StateDirectory`.

## Ограничения и приватность

- Доступность TCP/443 не гарантирует работу DNS, HTTPS или всех сайтов.
  Captive portal и фильтрация тестовых адресов могут влиять на результат.
- Если ни один адаптер не подтверждён, метрики не меняются.
- Ошибка Windows «доступ к сокету запрещён» означает неизвестную доступность,
  а не обрыв интернета. Например, Kill Switch VPN может запрещать прямые пробы.
  Для IPv4 добавлен адрес Яндекса, полезный при российских split-tunnel правилах.
- Свои метрики маршрутов, превышающие диапазон политики, не переписываются.
- Используются адреса Cloudflare, Google и Яндекса; передаётся только TCP handshake,
  без содержимого файлов. Нет аналитики, передачи логов и фоновых speedtest.
- Локальные файлы состояния содержат названия и GUID адаптеров. Не публикуйте их
  вместе с конфигурациями VPN, ключами и другими личными данными.

Для разрешённых вашей сетевой политикой адресов можно добавить в `config.json`
массивы `probeIPv4` и `probeIPv6` с IP-адресами серверов, принимающих TCP/443.
Не используйте локальный шлюз как доказательство работоспособности интернета.

## Проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Core.ps1
```

Проверяются классификация USB-модема, приоритеты, потеря интернета при живом
кабеле, гистерезис, раздельное состояние IPv4/IPv6 и сохранение метрик VPN.
CI выполняет проверки в Windows PowerShell 5.1 и PowerShell 7.
